# Changelog

All notable changes to this project are recorded in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, a minor release may contain breaking changes; each one is listed under *Changed* or *Removed* and never made silently.

## [Unreleased]

### Added

- Host settings (spec 05, [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md), [ADR 0009](docs/adr/0009-one-database-alias-per-app.md)): a settings module ends with `globals().update(neolith.host.build_settings([...], globals()))`. The builder reads each hosted app's declaration before settings exist and builds `INSTALLED_APPS` (hosted apps, `NEOLITH["UNDECLARED_APPS"]`, batteries, then `neolith`), `DATABASES` (`default`, `{}` in a closed host, and one alias per app with a database, from `NEOLITH["DATABASES"]`) and `DATABASE_ROUTERS`; it refuses those three in the deployer's input, an unknown `NEOLITH` key, an app whose import reads a setting and a silenced `neolith.E` id. A refusal is final for the process and leaves Django without settings. The first set-up compares the settings Django holds with what the host builds (`neolith.E005`), and set-up adds `neolith.E002` to `E004`, `E015` and `E016`; after set-up an override of `NEOLITH` may change `REQUEST_DEADLINE` only, and `DATABASES` and `DATABASE_ROUTERS` cannot change.
- Boot (spec 05, [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md) Decision 7): the root middleware's constructor boots the host once per process: `ROOT_URLCONF` is set and imports, `neolith.W001` runs again once the URLconf is loaded, and every schema is read, each hosted app's on its own alias and each app with migrations on a real `default`, refusing an in-memory or missing SQLite database, an unapplied, inconsistent or conflicting migration, a hosted app with a database and no migrations, and a migration that depends on another app (`neolith.E007` to `E013`, `E018`). The refusal is kept for the process. `neolith.testing.boot()` boots a test session without the schema read.
- `neolith run <app> [<app> ...] --settings <module> [--bind <host>:<port>]` (spec 05, [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md) Decisions 9 to 12), also `python -m neolith run`: boots the named apps in one closed host from a module of the deployer's names, runs the phases in order and serves only once Boot has passed, with Django's development server, which is not for production. On `SIGINT` or `SIGTERM` it stops accepting connections, closes idle ones and serves no request that begins after, and gives each request in flight until the request deadline, or 30 seconds when there is none; a second signal stops at once. It exits 0 when every request finished, and 1 with a line per request it cut. Refusals print as `neolith: <line>` with status 1; a mistake in the arguments exits 2.
- The migrate step: `neolith migrate <app> [<app> ...] --settings <module>`, and the `migrateapps` command for a host built by a settings module, apply each hosted app's migrations to its own database, in the order given, and on a real `default` the migrations of apps without a declaration. Before touching a database they refuse a hosted app with a database and no migrations, a migration that depends on an app whose records live in another database, and, in any installed app, migrations that do not load or conflict, which Django's `migrate` judges over the whole graph. They stop at the first failure and name the apps migrated, the app that failed with the migrations its database records as applied, and the apps not migrated. `migrateapps --check` reports what Boot would refuse and writes nothing.

## [0.1.0a1] - 2026-11-16

### Added

- Contracts (spec 01): `@contract` on a `Protocol` class, `@action` with `idempotent=`, `@implements`, and `Contract.of(...)` with a neutral description of the actions and their JSON Schemas. Identities, action names, request and reply types and implementations are checked when the module is imported, and fail with `ContractDefinitionError`.
- Contract errors (spec 01, [ADR 0008](docs/adr/0008-typed-contract-errors-in-both-modes.md)): `ContractError` with a `kind`, a `message` and a detail in `data`, and `@action(errors={...})` to declare an action's own error kinds with their detail records. Declared kinds are checked when the contract is declared, may not use a standard or reserved kind's name, and appear in the neutral description. A kind the receiver does not know is held with an untyped, read-only detail.
- `Action` gains `errors`, a frozen mapping from each declared kind to its detail record, empty by default.
- `@action` marks a method once, and implementation methods are not marked, including through wrappers such as `functools.cache` or `property`. `@implements` reads the implementation class statically, so it never evaluates a lazy attribute.
- Wire encodings (spec 01, [ADR 0019](docs/adr/0019-wire-encodings-of-the-portable-forms.md)): the neutral description states each form's range or pattern. Integers are limited to ±(2^53 − 1) and numbers to the finite doubles. `neolith.Duration`, `neolith.Decimal128` and `neolith.Binary` ([ADR 0020](docs/adr/0020-wire-forms-pydantic-writes-otherwise-are-neolith-annotated-types.md)) are `Annotated` types for durations, decimals and bytes that read and write exactly their wire forms (`"1.500s"`, `"-12.50"`, `"_w=="`); a plain `timedelta`, `Decimal` or `bytes` field is refused, naming the type to use. `Binary` reads base64url from JSON text only, so a receiver validates the text itself (`model_validate_json`). A default is refused unless Pydantic writes it in its form.
- The call context ([ADR 0017](docs/adr/0017-call-context-explicit-at-the-action-ambient-for-propagation.md)): `neolith.CallContext`, a frozen value with the principal, the trace, the deadline, the idempotency key and the calling app of one call, and `neolith.Principal`, a frozen issuer, subject and claims. An implementation's action that reads the context takes it after the request, as `(self, request, ctx: CallContext)`; `@implements` accepts that shape and `(self, request)`, and no other.
- App declaration (spec 05, [ADR 0021](docs/adr/0021-an-app-declares-itself-on-its-neolithappconfig.md)): `NeolithAppConfig`, whose subclass declares an app in class attributes: `name`, `label` (the app's name), and optionally `provides`, `requires`, `resources` and `batteries`, each a tuple. `Provided(<contract class>, implementation="<module>.<Class>", principal_from=(...))` is one entry of `provides`, with the calling apps that may assert a principal. The class is checked when it is defined, and `DeclarationError`, a subclass of Django's `ImproperlyConfigured`, lists every refusal of one class. A config class holds no other public name and cannot be subclassed once it declares. A declared app in Django's global registry needs `"neolith"` in `INSTALLED_APPS`.
- The host's set-up (spec 05, [ADR 0021](docs/adr/0021-an-app-declares-itself-on-its-neolithappconfig.md), [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md)): `"neolith"` is an installed app whose `ready()` resolves every hosted app's `requires` to a provider in the host and validates every provided contract's implementation: imported by its own `<module>.<Class>` path inside the providing app, checked against the contract and built once with no arguments. Every refusal, with each unknown identity that `connect()` was asked for, is listed in one `DeclarationError`. A later set-up with the same hosted apps builds a fresh table, and one with other hosted apps is refused.
- `neolith.connect("<contract>.v<N>")` returns a `neolith.Connector` that holds only its identity and may be made at import. Only `connect()` makes one: the class cannot be called or subclassed. A call through it is `neolith.UsageError`, a `RuntimeError`, until set-up has passed, as is an identity the host does not know once it is set up.
- The calling app (spec 02, [ADR 0017](docs/adr/0017-call-context-explicit-at-the-action-ambient-for-propagation.md) Decision 6, [ADR 0021](docs/adr/0021-an-app-declares-itself-on-its-neolithappconfig.md) Decision 9): a call from a scope whose app does not require the contract is `neolith.UsageError` before its principal is resolved, and an app with no declaration requires nothing. In-process, the provider's side refuses a call from no app with `unauthenticated`, and one carrying a principal from a calling app its `principal_from` does not list with `permission_denied`, before the action runs; a call with no principal is not checked against the list. A connector call made in no scope, or in one that has closed, raises `neolith.UsageError` instead of a plain `RuntimeError`.
- The command scope (spec 02, [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md) Decision 8): `with neolith.command_scope("<label>", principal=..., timeout=...):` opens a root for a hosted app, for a command or background work. Its calls call as that app, with the principal given and a deadline only when a timeout is given, counted from entry, under a new trace; a scope opened inside another takes nothing from it. It closes on exit, however the block ends, and is entered once. An app that is not hosted, a host not yet set up and a second entry are `neolith.UsageError`, as is an exit where the scope is not current, or is current in another context than it was entered in, such as a scope held across a generator's `yield`; that scope still closes, and a signal to stop the block ends with propagates with the report as a note. The refusals for a call outside `requires` and for a missing or closed scope now name `neolith.command_scope`.
- The request root (spec 02, [ADR 0017](docs/adr/0017-call-context-explicit-at-the-action-ambient-for-propagation.md) Decision 4, [ADR 0022](docs/adr/0022-the-app-host-builds-settings-and-checks-before-it-serves.md) Decision 6): `neolith.middleware.RootMiddleware`, listed first in `MIDDLEWARE` and once, opens a root for each request with the deadline `NEOLITH["REQUEST_DEADLINE"]` (30 seconds when absent, none when `None`), counted from the request's start. Once the view is resolved, the root belongs to the app whose code serves it, a class-based view's `view_class`, a partial its function's, a wrapper defined in an installed app other than Django's own that app's code whatever `functools.wraps` copied onto it, a wrapper whose code is no app's, one Django supplies such as `login_required` or one in the project, the code it wraps, a copied `view_class` or `model_admin` trusted only on the function that set it, and wrappers judged recursively so they compose, and a wrapper's `__wrapped__` followed only into a hosted app's code; for an admin view, the most derived class of its `ModelAdmin` in a hosted app or the project, or the model's app when there is none (an app's wrapper over that view is its own app's code); a view in no installed app, and anything that runs before the view is resolved, calls from no app and is refused. The root stays open while a streamed body runs, and the body's own closers run inside it; it closes when the response is done, so a call kept past it is `neolith.UsageError`. A `FileResponse` over a plain file is left unwrapped for `wsgi.file_wrapper`; any other file-like object is read inside the root.
- The host's checks before it serves (spec 05): set-up runs the system checks tagged `neolith` and raises every error in one `ImproperlyConfigured`, whatever `SILENCED_SYSTEM_CHECKS` says: `neolith.E001` for a missing `NEOLITH`, one that is not a `dict`, an unknown key or a `REQUEST_DEADLINE` outside a finite 0.001 to 9999999.999 seconds; `neolith.E006` for a `MIDDLEWARE` without the root middleware first, or with it twice. Set-up and the root middleware's constructor judge `MIDDLEWARE` by one rule, counting the class under any path or a subclass; the constructor also refuses a process whose host is not set up; a request that arrives while the host is not set up is refused. `neolith.W001` warns about a registered admin whose code is in no installed app, by the rule the binding uses, and set-up logs it unless it is silenced.
- Each app's database (spec 05, [ADR 0009](docs/adr/0009-one-database-alias-per-app.md)): a hosted app that declares the `database` resource lives on its own alias, named by its label. `neolith.routers.AppRouter` keeps its models there and sends every other label to `default`, from labels alone: reads, writes and migrations go to the label's home, and relations are allowed only within one home, so two apps cannot share a transaction. Set-up refuses a hosted app with models and no `database` (`neolith.E014`) and a table name that `default`'s backend shortened (`neolith.E017`).
- Runtime dependency on Pydantic v2 ([ADR 0006](docs/adr/0006-contracts-are-typed-and-published-as-openapi.md)).
